*bibframe-json* is a [JSON
Schema](https://json-schema.org/understanding-json-schema/reference) that
provides a consistently shaped JSON representation for
[BIBFRAME](https://bibframe.org) data, in the spirit of [Linked Open and Usable
Data](https://linked.art/loud/) (LOUD). Conforming JSON documents are still
JSON-LD and valid RDF. It is meant to simplify, not to replace.

:::note[Who is it for?]
*bibframe-json* grew out of the [Blue Core](https://bluecore.info/) project,
but the JSON schema is meant to be shared by like-minded people working with
BIBFRAME JSON data. It is published as [v0](/versioning/), which
means it can still change in ways that break documents written against it. v1 is
not far off, and is the point at which it becomes something to build on. Until
then it is as much a provocation as a specification, so if you have ideas or
concerns please consider [contributing](/contributing/).
:::

Just as the [International Standard for Book
Description](https://en.wikipedia.org/wiki/International_Standard_Bibliographic_Description)
(ISBD) provides a standard, human-readable form for bibliographic information on
catalog cards, *bibframe-json* prescribes a consistent JSON serialization for
BIBFRAME data, for building tools and workflows that don't necessarily require
RDF parsing and processing.

Below is the same record as *bibframe-json*. If you understand JSON but are new
to JSON-LD you may be surprised by a few keys that are specific to the JSON-LD
syntax:

* `@context` names the bibframe-json JSON-LD context which defines the vocabulary the other keys that are present in the document
* `@id` identifies the resource being described, in this case the Instance
* `@type` lists the classes the identified resource belongs to

You will notice that this is a [linked description](/linked-description/), so `instanceOf`
holds the Work's URI and stops there. A [bounded description](/bounded-description/) of the same Instance embeds that Work instead,
and is what you would send someone who doesn't want to (or is unable to) fetch
it.

## What the shape guarantees

- a JSON object framed for a particular BIBFRAME resource (not a JSON-LD @graph of triples)
- predictable vocabulary terms (e.g. "title" instead of "bf:title" or "http://id.loc.gov/ontologies/bibframe/title")
- every property value is an array, even when it's one value
- references are plain URI strings, not `{"@id": ...}` wrappers
- no blank node carries an `@id`
- a value object has `@value` and at most one of `@type` or `@language`
- `@type` is always a list of classes on a node, and a datatype string on a value
  object.

## The files

Plain JSON, served from this site, with no dependency on the Python that
maintains it.

| | |
| --- | --- |
| [`https://bibframe-json.org/v0/context/bibframe.jsonld`](https://bibframe-json.org/v0/context/bibframe.jsonld) | the JSON-LD context that produces the shape, 251 terms |
| [`https://bibframe-json.org/v0/schema/linked.json`](https://bibframe-json.org/v0/schema/linked.json) | a [linked description](/linked-description/) of a Work, Instance, Hub or Item |
| [`https://bibframe-json.org/v0/schema/bounded.json`](https://bibframe-json.org/v0/schema/bounded.json) | a [bounded description](/bounded-description/) |
| [`https://bibframe-json.org/v0/schema/ontology.json`](https://bibframe-json.org/v0/schema/ontology.json) | BIBFRAME's own domains and ranges |

The schemas reference each other relatively, `{"$ref": "Ref.json"}` and
`{"$ref": "linked.json"}`, so they resolve against wherever you serve them
from, this site or a copy on your disk.

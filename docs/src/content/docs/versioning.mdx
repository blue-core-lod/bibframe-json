---
title: Versioning
---

The context and the schemas are published under a version segment:

```
https://blue-core-lod.github.io/bibframe-json/v0/context/bibframe.jsonld
https://blue-core-lod.github.io/bibframe-json/v0/schema/dialect.json
```

A document names a context and a `$ref` resolves against a `$id`, so both are
promises. The segment is what lets a promise made today still hold after the
shape has moved on.

It sits above the trees rather than inside them, so a schema's references
never change: the split files stay siblings within their version, and
`{"$ref": "Work.json"}` resolves the same whether there is one version or six.

## What moves it

Only a change that invalidates documents written against the version before
it. Removing a term, renaming one, or changing a term's `@type` or
`@container`, because each of those changes what the same JSON means. Adding a
term does not, and neither does a new definition, a clearer description or a
tightened constraint that nothing conforming was relying on.

`example/` and `conformance/` carry no version. They are illustration and test
material that tracks the current version; nothing names them in a document.

## v0 is not settled

**v0 may change in place, without notice.** It is here so that the shape can
be used and argued with, not so that it can be built on. Freezing starts at
v1: from then on a version's bytes never change, and v0 stays served as it was
last published.

The Python package follows ordinary semantic versioning and moves for any
change, including shipping a new artifact version. Adding v1 while v0 is still
shipped is additive, so it is a minor release; a major release means dropping
a version or changing the Python API.

## Reading a document without fetching anything

A document names its context by URL, and both rdflib and pyld will go and
fetch that URL while parsing. Over a table of records that is slow enough that
people strip `@context` on write and put a hardcoded one back on read, which
works and loses the one thing the URL was telling you: which version framed
the document.

The package ships every context it has published, so the URL can stay in the
document and cost nothing.

With **pyld**, install the loader once:

```python
import bibframe_json
from pyld import jsonld

jsonld.set_document_loader(bibframe_json.document_loader())
jsonld.expand(document)          # no network, whatever version it names
```

Anything the package does not ship falls through to pyld's own loader, so this
does not stop you resolving someone else's context.

With **rdflib**, hand the context in rather than letting it resolve one:

```python
import bibframe_json
from rdflib import Graph

url = document.pop("@context")
Graph().parse(
    data=document,
    format="json-ld",
    context=bibframe_json.context_for(url),
)
```

`context_for()` returns `None` for a URL this package does not ship, which is
how you tell "not ours" from "ours and empty".

## Asking for a particular version

```python
import bibframe_json

bibframe_json.VERSIONS          # ("v0",) oldest first
bibframe_json.CURRENT           # "v0", the one written today
bibframe_json.context("v0")     # that version's context
bibframe_json.schema("dialect", "v0")
bibframe_json.context_url("v0")
```

Asking for a version the package does not ship raises `ValueError` rather
than reading a path that happens not to exist.
